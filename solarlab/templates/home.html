About the project

A solar panel turns sunlight into electricity, and it works best when the light hits it straight on. When the panel is tilted away, the same beam of light spreads over a larger area, so each part of the panel receives less energy and the output drops.

Solar Lab lets visitors see this for themselves. Instead of reading a formula in a textbook, they move a slider to tilt a virtual panel, change the sunlight and the weather, and watch the estimated power change straight away.

Two panels can be set up side by side with different conditions, so the difference is easy to see. Guided experiments show how angle and clouds change the output, and a graph follows the results as they happen.

Solar Lab is an educational model, not a weather forecast. Real panels are also affected by temperature, dust, shading and electrical losses, which this simplified model leaves out.

The science behind it

The simulator applies Lambert's cosine law, which says the light a surface receives depends on the cosine of the angle at which it strikes. That gives a simplified model of how much power a panel produces. The formula started small and grew as weather and shade were added, which the How it works page explains step by step:

P = Pmax × w × I × (1 − s) × cos(θ)
P
Estimated output power
Pmax
Maximum rated power of the panel
I
Relative sunlight strength, from 0 to 1. It is lower when the sun is low in the sky.
w
Weather factor: 1.0 sunny, 0.6 partly cloudy, 0.25 cloudy (assumed values)
s
Fraction of the panel in shade, from 0 (none) to 1 (all). It is 0 unless shade is switched on.
θ
Angle between the sunlight and the line pointing straight out of the panel. Output is zero beyond 90°.

How it is built

Solar Lab is a small website of seven pages that share one design: Home, About, Science, Features, Experiments, Simulator and How it works. Each page is written by hand in HTML, styled with one CSS file and made interactive with a little JavaScript.

  1. Structure (HTML). Headings, sections, tables and buttons give every page its content and meaning.
  2. Style (CSS). One stylesheet controls colours, spacing and layout. It is written for phones first, then adds rules for tablets and laptops. Colour variables make the light and dark themes possible.
  3. Behaviour (JavaScript). The theme button, the phone menu, the simulator's calculations, the graphs and the saved experiment results.
  4. Serving (Flask). A short Python program sends each page to the browser. It can run on a laptop or on a hosting service.

Keeping each job separate makes the project easier to understand and fix. If a page looks wrong, the problem is in the HTML or CSS. If a button does nothing, it is in the JavaScript. If a page will not load, it is in the Flask routes.

Want the details? The How it works page explains every function and how the formula changed as factors were added.
